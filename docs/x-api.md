# 創作のための複合分析（v1.4.0）

公開Webの背景情報にXの表現・反応を加え、生成AIが比較して漫画・動画・小説の企画へ変換します。Xは補助情報源です。X向け投稿文とX単独分析は提供しません。

| 役割 | 接続 | 用途 |
| --- | --- | --- |
| 背景・話題の取得 | 公開Web/RSS | 常に使用 |
| 世間の表現・反応の取得 | X API（任意） | 公開Webに追加 |
| 横断分析と創作 | OpenAI または Gemini | どちらか1つを使用 |

## 操作

1. 漫画（初期選択）・動画・小説から媒体と想定読者を選びます。
2. 「Xを使う」を選ぶと公開WebにXの補助情報を加えます。初期値は「Xを使わない」で、キー入力だけでは通信しません。
3. XのBearer Tokenと、OpenAIまたはGeminiのAPIキーを接続します。Xを使わない場合は生成AIのキーだけで開始できます。
4. 「情報収集・分析・企画作成を開始」で収集・横断分析・3案の創作まで進みます。漫画用のX検索は人間関係・仕事・家族・日常の悩みを初期条件とし、検索条件から変更できます。
5. 各案の「複合分析 → 物語への反映」に、両情報源の参照と、人物・対立・展開への変換理由を表示します。片方だけの参照、不正な参照、理由の欠落は生成成功として扱いません。関連が弱ければ差異と限界を示し、因果関係を捏造しません。
6. 各案の「参考文章を生成」で本文・台本へ進めます。資料と取得指標は下部の折りたたみから確認できます。

初回開始後のカテゴリ・読者・RSS期間変更は再分析を実行します。X設定変更は次回取得から反映。「Xを使わない」では接続済みでもXへ通信しません。Xが0件または失敗した場合は、複合分析の成功として扱いません。

## キーの違い

- Consumer Key（API Key）とSecret：アプリを識別する情報。
- Access TokenとAccess Token Secret：OAuth 1.0aでユーザー権限を使うための組。
- 今回使うBearer Token：公開データをアプリ専用認証で読み取るトークン。OAuth 2.0のアクセストークンの一種ですが、OAuth 1.0aの組とは別です。

[X Developer Console](https://console.x.com/)の対象アプリ → Keys & Tokens → ベアラートークンで確認・発行します。トークンはチャットや共有ファイルへ貼り付けず、アプリの専用欄に入力してください。キーはページ内のメモリだけに保持し、再読み込みで消えます。XのキーはX APIへだけ送信し、生成AIや保存レポートに含めません。

## 取得範囲・費用

X検索は固定宛先 `https://api.x.com/2/tweets/search/recent` を使うローカル版専用機能です。GitHub Pagesの静的デモではX検索を提供しません。ローカルでは `npm install`、`npm run dev` の後、ポート5180の通常画面を開きます。`npm run preview` もX中継に対応します。

1検索は1リクエストだけで、自動ページ送り・巡回・再試行はしません。同一条件の結果は5分以内なら分析時に再利用します。検索は全投稿の網羅や人気順を保証しません。関連度順でも反応が少ない投稿を含みます。

2026-11-13確認の標準単価はPost Readが1件$0.005、User Readが1件$0.010。表示する参考上限は、投稿上限×$0.005に、投稿者取得を選んだ場合は投稿上限×$0.010を足した概算です。10件・投稿者追加なしなら$0.05。実請求は取得件数・重複・契約条件等で異なり、生成AI料金は別です。残高不足や権限制限はエラー表示し、RSS成功でXの失敗を隠しません。

## 実測値と判断用の指標

いいね・リポスト・返信・引用・表示回数・ブックマークはAPIが返した値を使います。0と未取得を区別し、未取得項目を補完しません。反応数は、いいね+リポスト+返信+引用の合計。表示100回あたり反応は人数や賛同率ではありません。

増加速度は同じ投稿を1分以上離して2回観測でき、反応数が減少していない場合だけ差分/時間を表示します。初回は「未計測」です。観測履歴はページ内に最大500投稿まで保持します。

Xの根拠選定用スコアは、反応量40%・フォロワー規模で補正した反応量40%・投稿の新しさ20%の目安です。反応量はlog(1+反応数)/log(1001)、規模補正はlog(1+反応数×1000/フォロワー数)/log(101)を各1で打ち止めにし、新しさは1/(1+経過時間/24)。フォロワー未取得時は規模補正分にも反応量を使います。バズ確率ではなく、RSSとの人気の直接比較でもありません。混合取得ではRSSとXの両方を根拠に残します。

JSON・Markdown・DOCXは各企画、参照した情報源、物語への変換理由を保持します。

公式資料：[認証](https://docs.x.com/fundamentals/authentication/overview)、[検索](https://docs.x.com/x-api/posts/search/introduction)、[公開指標](https://docs.x.com/x-api/fundamentals/metrics)、[料金](https://docs.x.com/x-api/getting-started/pricing)。

## 鮮度と再検索

初期期間は直近24時間です。RSS項目の配信日時で選択期間内だけを採用し、日付不明・未来・期間外の項目は除外します。RSS配信日時は元記事の初出日時や出来事の発生日時とは異なる場合があります。Xは投稿日時です。取得日時で不明な日付を埋めません。画面には出典日時と今回の取得日時を別に表示します。

再検索では既定のX検索語も切り替え、直前のキャッシュを使わず再取得します。明示した検索語は維持します。同じページで使ったURL・類似見出しを除外し、過去18案の題材・主人公・対立・結末を生成AIへ渡します。同題・近似した本文は検査で拒否します。意味が同じ言い換えをすべて機械的に検出できる保証はありません。公開WebとXの新しい根拠が揃わない場合は取得不足を表示し、以前の資料を新しい結果と偽りません。ページ再読み込みで履歴とキーは消えます。

RSSの重み・共起・掲載指標は取得資料から計算した参考指標で、実際の反応数やバズ確率ではありません。Xの実測反応とは区別します。

生成AIの内容検査に失敗した場合は、同じモデルへ理由を渡して1回だけ修正します。利用不可・通信失敗時の候補切替を含め、各処理は最大3試行です。各応答は最大4分で待機を打ち切り、時間切れでは自動再試行しません。失敗を成功結果やダミー企画で埋めません。
